## API 输入

修复手机聊天页点击“API 提供商”后因命名路由返回类型转换异常而无法打开设置页的问题。手机工具栏提供直接入口；设置页打开后，点击 API Key 或 Base URL 会请求焦点并唤起软键盘。

同时修复主 LLM 表单每输入一个字符就被重新创建、失去焦点的问题。输入时保留光标、输入法组合文本与密钥显隐状态；切换 Profile 或提供商预设时同步显示对应的字段和数字参数。

## JSON 创建

角色和故事的 JSON 创建、AI 生成后的 JSON 预览共用格式检查界面。出错时保留可编辑原文，显示具体字段路径或 JSON 语法行列；兼容处理与未识别字段在创建前列出，确认后才提交。

支持的兼容处理：

- Markdown JSON 代码块、字符串外的行注释和块注释、对象或数组末尾多余逗号。
- 字符串外的全角空格、不换行空格等 Unicode 空白，以及全角大括号、方括号、冒号和逗号；字符串内部原样保留。
- 中英文常见字段别名，例如 `名称` → `name`、`性格` → `personality`、`当前状态` → `currentStates`。
- 大小写、空格、下划线和连字符差异，例如 `fixed_input` → `fixedInput`。
- 长英文标准字段的唯一、单字符拼写差异，包括相邻字符颠倒；短字段与用户定义的状态 ID 不做模糊猜测。
- `data` / `character` / `story` 等单对象包装，以及只有一个角色对象的数组。
- 列表字段的单个文本作为一项保留；数字和布尔值转为文本；设定键值对象转为列表。
- 故事状态缺省版本按 0 导入，文本整数版本可转换；缺少状态 ID 时使用名称，当前值的键可按精确状态名称映射至 ID。

示例：

```json
{
  "角色名称": "林夏",
  "fixed_input": "你是一名在雨城工作的侦探。",
  "personality": "理性、克制",
  "当前状态": {"好感度": 10}
}
```

JSON 语法错误会显示行、列、实际出错字符、完整 Unicode 编码和带箭头的附近原文，例如 `出错字符：“（U+201C）`；错误位于文件末尾时显示 `EOF`。字段类型无法兼容时，会显示例如 `$.personality[1]：需要文本，实际是对象`。状态名称或 ID 重复、当前值没有对应定义、多个别名指向同一字段但内容冲突时，要求用户修改，避免猜测覆盖。未知字段会明确列出为不导入；需要保留的内容可移入 `fixedInput`。

这些兼容仅用于创建导入，不放宽运行中的状态版本校验、剧情回滚和备份校验。兼容解析在本地完成，不增加模型请求。
