# 按故事配置状态与持久化回滚

角色/故事对话使用用户手动配置的记录项。撤回、重发和历史删除都会恢复对应位置之前的正文、配置、当前值和完整记忆，不调用模型重建。

## 使用方式

- 创建联系人时在“需要记录的状态”中添加记录项；已有故事从“记忆档案 → 故事状态”编辑。
- 每项包含名称、记录说明、初值、更新规则；可改名、排序、删除和修改当前值。名称变化不改变稳定 ID。当前值留空表示清空。
- 所有记录项均由用户定义。应用不预置场景、衣着、人物或动作阶段字段，自然语言创建角色也不会自动创建记录项。
- 长按用户输入可以“修改后重发”。长按用户输入或回复可选择“删除本轮及之后内容”；确认框显示影响轮数。
- 旧记录仅在目标轮之前有完全匹配的完整检查点时可回滚；缺少恢复依据时拒绝删除，避免只删掉气泡。老检查点没有锁/修订元数据时，若当前存在相关记录也会保守拒绝。

## 状态协议

`Contact.continuity` 保存 `revision`、按显示顺序排列的 `definitions` 和以 ID 为键的 `values`。对外 JSON 定义使用 `id / label / type / description / defaultValue`，可选 `enum / updateRule`；兼容旧 `name / initialValue`。定义进入稳定 system 前缀，完整当前值进入本轮动态上下文，不参与摘要或通用列表/行长裁剪。字段说明和完整示例见 [Continuity JSON](CONTINUITY_JSON.md)。内部持久化继续使用原名称键，避免破坏旧版逐字段比较的可逆剧情日志。

`roleplay-memory-v5` 的 `memoryPatch.stateTransition` 示例：

```json
{
  "baseRevision": 3,
  "changes": [
    {"key": "state-clue", "from": "门锁有划痕", "to": "门锁有划痕；窗台发现脚印"}
  ]
}
```

本地整批校验版本、字段归属、重复 ID、旧值和字符串类型。省略项保持原值，`to: ""` 明确清空。用户填写的自然语言更新规则通过提示词约束；本地不会声称已验证语义。旧 `currentStates` 和旧固定路径值迁为普通自定义项；改名和删除后不会因兼容字段而复活。

## 事务与恢复依据

SQLite schema v4 新增三张表：

| 表 | 作用 |
|---|---|
| `story_heads` | 分支版本和记忆元数据 |
| `story_turns` | turnId、联系人/分支、用户输入、消息起点、此前版本与请求状态 |
| `story_operations` | 联系人完整剧情数据和锁/修订记录的可逆变化 |

消息携带 `turnId`，本轮用户输入、回复、流式草稿及调试消息具有相同归属。操作差量递归比较映射，区分缺键和空值；列表保存公共前后缀之间的替换段，恢复时校验被替换的现值。差量涵盖知识、物品、事件与摘要标记、被淘汰节点、关系边、队列顺序、关键词和修订/锁信息。

1. 开始轮次持久化输入和 pending 记录，并推进分支版本。
2. 完整响应在本地通过校验后，正文、联系人、事件图、操作日志和自动检查点在同一事务提交；UI 随后发布成功状态。
3. 事务失败不会提交任何记忆变化。中止记录只保存 failed/cancelled 尝试；重启将遗留 pending 标记为取消。
4. 截断时逆向应用目标轮之后的日志，删除消息尾部、对应轮次/操作及失效检查点，并推进版本以拒绝旧预览。
5. 恢复后重新从数据库加载分页窗口和记忆元数据，不使用旧消息快照配合新分页起点写回。

Provider 使用统一操作互斥（比联系人级更保守），生成、分页、切换联系人/分支、状态编辑、记忆修订、回滚和备份恢复不会相互覆盖。SQLite 提交另行校验分支、版本和轮次位置。正文请求期间禁止截断；先停止生成后再删除。

自动检查点只保存消息位置和日志版本，不逐轮复制整段聊天正文；需要创建分支或导出时按需重建。独立分支拥有自己的日志和记忆。当前分支回滚时清理相关检查点并解除其他分支的来源链接，不删除独立分支已有内容。备份 v3 导出清理后的时间线及日志，恢复在单个事务中校验并写入；API 和应用设置不在备份内。恢复后的新检查点仍使用位置/版本形式。

## 调用成本

保留稳定提示词前缀、单份输出协议和既有 0–2 POST 的事件召回预算。状态维护与正文在同一个模型响应中完成，不增加状态提取、审核或记忆重建请求；不会因为正文短于固定字数自动重试。摘要仅在阈值满足时请求，并绑定实际提供的源节点。

v5 将正文 JSON 字段排在 `memoryPatch` 前，使流式界面可以先显示 `reply`；模型仍在内容规划阶段先确定事件摘要和状态变化。最近 4 条真实对话作为原生 `user/assistant` 消息发送，不再拼成低可信文本段。`knowledgeChanges` 和 `belongingChanges` 支持新增、替换和删除，本地 reducer 保留对旧版仅追加字段的兼容。

固定定义和角色设定不变时，system 可逐字复用。缓存是否命中及实际费用取决于供应商；本地测试验证请求结构和调用次数，真实模型的语义遵循与首轮达标率仍需实际对话评估。

## 回归验证

全部使用模拟模型和本地存储，不调用真实模型 API。真实 SQLite 测试覆盖完整记忆精确恢复、重启与连续撤回、历史删除后实际 Prompt 无污染标记、重发/修改后重发、流式取消、失败重试、检查点写入故障、配置写入故障、重复点击、生成期间删除、万条消息分页、跨摘要层与队列淘汰、分支隔离、检查点清理、备份恢复、损坏日志拒绝以及 v3 数据库升级。另有差量随机往返测试和编辑器交互测试。
